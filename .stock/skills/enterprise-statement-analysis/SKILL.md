# 企业财务报表分析（八看框架）

用财务报表解释企业做了什么、资源如何配置、利润如何形成、现金能否兑现，以及企业能否持续发展。核心原则：**利润是观点，现金是事实；资产质量是利润质量的结果；比率先用来提问，不用来下结论。**

本方法参考张新民《从报表看企业——数字背后的秘密》第5版的分析框架，以原创表述提炼；不复述书中的案例或长段文字。

## 适用范围

- 用户提供年报、季报、财务报表、报表摘录，或要求基于公开年报分析企业。
- 用户询问盈利增长是否扎实、现金流与利润为何背离、资产或债务质量、并购商誉、企业风险、股东权益价值或发展前景。
- 用户要求比较母公司与合并报表、判断控制性投资扩张效应、解释归母净利润与合并净利润差异。
- 仅问股价走势、技术指标或买卖点时，使用股票技术分析流程；仅问大盘环境时，使用市场周期评估流程。

## 快速开始（先跑脚本，再分析）

本技能自带两个脚本：`fetch_statements.py` 取 A 股年报数据，`analyze_statements.py` 计算指标、结构、信号和数据缺口。**不要手工重算脚本已经算出的指标。**

### 1. 确认对象与口径

确定企业、报告期间、币种和单位、报表范围（母公司/合并）、业务板块及分析目的。用户只给公司名称或代码时，默认使用最近 6 个年度报告；说明数据截止期。优先使用经审计年报及附注，其次才是数据接口。

### 2. 取数

Windows（cmd）：

```bash
"%PYTHON_EXEC%" stock-server/.stock/skills/enterprise-statement-analysis/scripts/fetch_statements.py --code 600519 --years 6 --out .tmp/600519-statements.json
"%PYTHON_EXEC%" stock-server/.stock/skills/enterprise-statement-analysis/scripts/fetch_statements.py --name 贵州茅台 --years 6 --out .tmp/600519-statements.json
```

Linux / macOS：

```bash
"$PYTHON_EXEC" stock-server/.stock/skills/enterprise-statement-analysis/scripts/fetch_statements.py --code 600519 --years 6 --out .tmp/600519-statements.json
```

脚本只输出一行摘要（代码、名称、行业、期间、输出路径、警告），完整数据写入 `.tmp/<code>-statements.json`。**不要**把完整 JSON 打印到对话里；需要核对时用 `read_file` 读取该文件的具体片段。

- 只取合并报表；**母公司报表公开接口通常不提供**。需要控制性投资/集团管理分析时，从年报“母公司资产负债表、母公司利润表、母公司现金流量表”抄录，按 `references/data-schema.md` 组装 `--parent` 文件。
- 金融行业（银行/保险/证券）使用专用报表模板，脚本会标记 `is_financial` 并只输出通用数据；核心利润、经营资产分类等指标不适用，需改用行业指标。
- 若接口失败或公司不在 A 股，改用年报 PDF/交易所披露/公司官网，按数据 schema 手工组装；**不要编造数字**。

### 3. 计算与诊断

```bash
"%PYTHON_EXEC%" stock-server/.stock/skills/enterprise-statement-analysis/scripts/analyze_statements.py --input .tmp/600519-statements.json --brief
```

快速判断用 `--brief`：只输出最新期指标、信号、数据缺口和待核实问题，token 更省；需要多年趋势表时去掉 `--brief`。

输出紧凑 JSON，包含：

| 字段 | 含义 |
|---|---|
| `metrics` | 逐期指标：收入、毛利、核心利润、营业利润、净利润、归母净利润、增长、利润率、ROE/ROA |
| `profit_structure` | 营业利润“三支柱两减值”：核心利润、其他收益、杂项收益、两项减值、残差 |
| `assets` | 经营资产/非经营资产规模、占比、经营资产报酬率、周转率 |
| `capital` | 商业债务/金融债务/股东贡献/利润积累“四度”，资产负债率、有息负债率、利息保障倍数 |
| `cashflow` | 经营现金流、核心利润获现率、折旧摊销、资本开支、自由现金流、融资净额 |
| `quality` | 应收/收入、存货周转、商誉/净资产、其他应收款/资产、在建工程/固定资产、费用率 |
| `parent_analysis` | 有母公司数据时：控制性投资占用资源、扩张效应、扩张倍数、母子公司利润/投资收益差异 |
| `signals` | 脚本按规则触发的**问题提示**（不是结论），含证据和期间 |
| `data_gaps` | 缺失数据及其影响 |
| `questions` | 需要查阅附注/公告核实的问题 |

需要 Markdown 速览时加 `--format md`；需要保存时加 `--out .tmp/<code>-analysis.md`。

### 5. 写报告

按“对象与口径 → 结论摘要 → 八看分析 → 三表核验 → 风险与反证 → 前景情景 → 待核实”组织。区分事实、推断和假设；冲突证据并列；不制造精确分数、目标价或买卖指令。

## 八看速查

| 维度 | 核心问题 | 深读 |
|---|---|---|
| 看战略 | 资产结构、控制性投资、资本引入方式、控股股东立场如何体现战略？ | `eight-views.md` §1 |
| 看经营资产管理与竞争力 | 现金、上下游、存货、固定资产、无形资产的配置能否支持竞争力和现金流？ | §2 |
| 看效益和质量 | 核心利润是否真实、可持续？利润由谁贡献、现金能否兑现？ | §3 |
| 看价值 | 账面净资产、评估值、交易价、股价分别意味着什么？ | §4 |
| 看成本决定机制 | 成本水平由治理、决策、管理还是核算决定？ | §5 |
| 看财务状况质量 | 资产、资本结构、现金流的质量如何？ | §6 |
| 看风险 | 经营风险与财务风险分别在哪里？风险信号是否已经发生？ | §7 |
| 看前景 | 经营、投资、融资/重组三条路径各自的前提是什么？ | §8 |

**三表关系**：资产负债表是资源与家底，利润表是期间能力与结果，现金流量表是活力与印证。现金流量表解释货币资金变化，利润表解释未分配利润和盈余公积变化；三表不一致时先解释口径、时点和会计处理，不要直接推断造假。

## 分析纪律

1. **先结构，后比率**：先看经营资产/投资资产、经营负债/金融负债、核心利润/杂项收益的结构，再看比率。比率只用于提出和检验问题。
2. **核心利润是经营分析的核心**：`核心利润 = 营业收入 − 营业成本 − 税金及附加 − 销售费用 − 管理费用 − 研发费用 − 利息费用`。不要用“营业利润率”或“销售净利率”代替核心利润率。
3. **利润必须用现金检验**：核心利润应产生经营现金流；但 1.2~1.5 倍是经验参考，存货周转低于 2 次、长周期行业、预收模式要按经营周期判断。
4. **区分经营资产与投资资产**：战略分析以母公司报表为基础；合并报表中控制性投资已被还原为子公司的经营资产。
5. **区分经营性负债与金融性负债**：高负债率不一定危险；预收/合同负债包含毛利，可能夸大负债率。真正要看有息负债率和偿债现金。
6. **母子公司不能混为一谈**：母公司净利润是分红基础，合并净利润是集团盈利能力，归母净利润用于每股收益和估值；三者差异本身是信息。
7. **警惕“三支柱两减值”失衡**：核心利润、其他收益（补贴）、杂项收益（利息/投资/公允价值变动）和两项减值，任何一项占比异常都要追问。
8. **资产质量是利润质量的结果**：利润最终落在资产上；应收、存货、其他应收款、商誉、在建工程的变化，往往比利润表更早暴露问题。
9. **先验数据，再下判断**：脚本会对年度间异常波动的应收/存货写入 `caveats`；若最新期数据可疑（新准则、重述、接口不完整），改用上一个完整年度做结构分析并注明。
10. **风险信号不等于风险发生**：区分“可能发生”“已经发生”“已被管理层应对”；给出触发条件和反证。
11. **不越界**：不编造缺失数据，不把关联方交易当独立交易，不把历史增速机械外推，不给个性化买卖指令。

## 默认输出

1. **对象与口径**：企业、期间、合并/母公司、币种单位、资料来源及审计情况。
2. **结论摘要**：3~5 条，分别写主要强项、主要疑点、总体判断和置信度。
3. **八看分析表**：

   | 维度 | 关键发现 | 报表/年报依据 | 含义与风险 | 置信度 |
   |---|---|---|---|---|

4. **三表交叉核验**：利润、资产变化、现金流和融资安排之间的重要对应或背离。
5. **结构与质量**：利润结构、资产结构、资本来源、现金流质量；有母公司数据时加控制性投资分析。
6. **风险与反证**：列出支持判断的证据、反向证据、可能失效的条件。
7. **前景与情景**：经营、投资、融资/重组路径，分别给基准、乐观、谨慎情景及关键假设。
8. **待核实事项**：缺失数据、需要查阅的附注/公告、需要管理层解释的问题。
9. **免责声明**：财务信息解读，不构成投资建议。

详细模板见 `references/output-templates.md`。

## 执行环境约束

- Windows 上的 `execute` 通过 **cmd.exe** 运行：不要用 `;` 串联命令（用 `&&`），不要用 `$(...)`、`export`、`source` 等 bash 语法。
- 运行 Python 用 `"%PYTHON_EXEC%"`；缺少 `requests` 时用 `"%PYTHON_EXEC%" -m pip install requests`。
- 不要使用 `cat` / `head` / `tail` / `wc` / `sed` / `awk` 等 Unix 工具；读文件用 `read_file`，搜索用 `grep` 工具。
- 文件工具使用相对路径（`.tmp/...` 或 `stock-server/...`）；不要传 `D:\...` 或 `/d/project/...`。
- 临时文件只能放在仓库根目录的 `.tmp/`；不要复制脚本到别处运行，也不要在技能目录里生成临时文件。
- 正常流程只需跑一次取数脚本和一次分析脚本；不要为了“补齐”缺失字段反复抓数或写探针脚本。缺失就写进 `data_gaps`。
